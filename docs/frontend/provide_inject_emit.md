provide/inject и emit решают разные задачи:

emit — для прямой связи родитель-ребёнок:
- Родитель точно знает, какие события бросает ребёнок
- Легко отслеживать поток данных — всё видно в шаблоне (@logout, @chat-created)
- Vue DevTools показывает все эмиты

provide/inject — для сквозных зависимостей:
- Когда нужно пробросить что-то через несколько уровней вложенности
- Типичные примеры: тема, текущий пользователь, глобальные функции типа showError

Почему showError через provide — ок:
- Это глобальный сервис, нужный в 5+ компонентах на разной глубине
- Пробрасывать через emit пришлось бы цепочкой: ChatView → App, CreateChatModal → App и т.д.

Почему @logout, @chat-created через emit — правильно:
- Это конкретные бизнес-события одного компонента
- Родитель явно подписывается — код самодокументирующийся
- Если заменить на inject, связи станут неявными — при чтении шаблона не поймёшь, кто что вызывает

Правило: если событие идёт от ребёнка к непосредственному родителю — emit. Если функция нужна "всем подряд" на разной глубине — provide/inject.
